# QuickJS-ng in Wisp

Upstream: https://github.com/quickjs-ng/quickjs

Vendored release: **v0.17.0**, commit
`6d46d07d04041b40f4f49eaa7fdebe44c314c699`, imported 2026-10-07.
This replaces the post-v0.11.0 snapshot
`d405777f7eefa22c17c12970317ef3d6e7658f5a`.

The import includes upstream's tracked source, generated bytecode and tables,
tests, examples, documentation and build files. Root Git configuration, GitHub
workflows and the external test262 submodule are omitted. Upstream formatting is
preserved, including existing trailing whitespace; do not run Wisp's formatter
across this directory.

## Local patches

- `quickjs.c`, `quickjs.h`: `JS_CloseContextJobs(ctx)` permanently prevents new
  jobs for a retired document and releases its pending jobs without running
  callbacks. It leaves other contexts' jobs and their order intact. Marking the
  context closed **before** releasing arguments also blocks FinalizationRegistry
  jobs created by that release or a later GC. Upstream's
  `JS_GetPendingJobContext()` only inspects the queue and does not replace this
  extension. `JS_DiscardContextJobs(ctx)` performs one-time removal after an
  execution timeout, suppressing new jobs while freeing arguments, then restoring
  the prior queue state. It allows later scripts to enqueue normally and never
  reopens a permanently closed queue. Tests are in `src/test/test_quickjs.c` and the Qt navigation cleanup
  regression.
- `quickjs.c`, `api-test.c`: propagate allocation/property-definition failures
  from `JS_SetPropertyFunctionList` instead of reporting success with a pending
  exception. Check accessor creation, release a getter if setter creation fails,
  and propagate lazy-property/value/alias failures. The API regression sweeps
  allocation budgets and checks rejection of a conflicting non-configurable
  property. Wisp also tests each binding's initialization under allocation limits.
- `quickjs.c`, `api-test.c`: avoid leaking the proposed prototype reference if
  `JS_SetPrototype` cannot copy a shared shape. Check and unwind failures in
  `JS_AddIntrinsicDOMException` instead of publishing incomplete initialization.
  Both have allocation-budget regressions, also exercised by Wisp's DOM setup.
- `CMakeLists.txt`: use `WISP_LIB_TYPE`; leave CLI/compiler off by default; gate
  upstream test executables on `WISP_ENABLE_TESTS`; keep the CLI support library
  out of the default build unless required; respect Wisp's `_WIN32_WINNT`; and
  preserve the existing Windows install exclusion. CLI/compiler install entries
  follow their build options.

The old portability patches are no longer needed: upstream uses a mutable
`longopt` in qjsc and const pointers for module/test-runner searches, replacing
our `strchr`/`strrchr`/`strstr` casts. Its x87 macro now begins with `(void)0;`,
allowing expansion after a label in C11 without our extra null statement.
No Web API implementations or site workarounds are patched into the engine.

## Updating

Import the complete next release, including `gen/` and generated builtin headers;
its bytecode format must match the engine. Reapply only the patches above and
review whether upstream has replaced them. Keep Wisp's generated Window/Console
bindings separate: their source is `utils/qjs_binding_generator.py` and WebIDL,
with output generated in the build directory.

Build and run `test_quickjs`, `qt_js_script_order`, `qt_js_timers`, `qt_js_dom` and
`qt_js_navigation_cleanup` in a Wisp Qt debug build. Also run the vendored C API,
regexp and local JS tests. A standalone build can use:

```sh
cmake -S contrib/quickjs-ng -B /tmp/wisp-qjs-tests -GNinja \
  -DCMAKE_BUILD_TYPE=Release -DWISP_ENABLE_TESTS=ON \
  -DQJS_BUILD_CLI=ON -DQJS_BUILD_QJSC=ON -DQJS_ENABLE_INSTALL=OFF
cmake --build /tmp/wisp-qjs-tests
/tmp/wisp-qjs-tests/api-test
/tmp/wisp-qjs-tests/lre-test
(cd contrib/quickjs-ng && /tmp/wisp-qjs-tests/run-test262 -c tests.conf)
/tmp/wisp-qjs-tests/function_source
```

`tests.conf` runs upstream's local suite; this is **not** a run of the external
ECMAScript test262 repository. Review navigation cancellation whenever adding a
new source of jobs, timers, events or asynchronous work.

Upstreaming proposals are recorded in
[`src/docs/quickjs-upstreaming.md`](../../src/docs/quickjs-upstreaming.md).
